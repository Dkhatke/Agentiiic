# CONTEXT: living build log

Updated after every phase. Read this first when resuming. The roadmap is in [PLAN.md](PLAN.md); this file records what was actually done, with what, and why.

## Project
Personal, lightweight, permission-gated agent for building projects (code, research, ideas, college work). Not a thin LLM wrapper: it has a tool registry, permission gate, sandbox, redaction, audit log and provider router. Repo: https://github.com/Dkhatke/Agentiiic (the user allowed pushing directly to `main` for this repo).

## Stack and why
| Choice | Why |
|---|---|
| Python 3.12 via `uv` (system Python is 3.9) | stdlib `tomllib`, modern typing |
| `httpx` is the only runtime dependency | keep install and idle footprint small |
| TOML for config and profiles | stdlib parser, no PyYAML |
| OpenAI-compatible HTTP API for all providers | one client covers OpenRouter, Ollama, Groq, Gemini compat |
| SQLite and JSONL (no Postgres, Redis, Docker, vector DB) | lightweight; deferred until needed |
| macOS `sandbox-exec` for shell | confines writes and network with no Docker VM |
| Machine: Apple Silicon arm64, 16 GB RAM, Ollama not installed yet | a 3-4B local model is comfortable |

## Decisions
- Agents are **profiles** (TOML) over one engine, not separate programs.
- Keys come from env vars only. The user adds an OpenRouter key and/or Ollama later; the agent was built first.
- `tool_mode = "text"` per provider lets weak or free models work without native tool-calling (idea from mini-swe-agent).
- The ChatGPT "NEXUS" design was reviewed. Kept: manifests, state persistence, branch per task, data-classification idea. Deferred: Postgres/pgvector, Redis, Docker, Next.js, LangGraph, multi-user auth.
- Never commit to `main` from the agent's `git_commit` tool (this repo's `main` pushes are the user's explicit exception).

- Validated once against Groq gpt-oss-120b (4/4 evals). Not yet validated on the OpenRouter free models or Ollama; free models vary a lot, so rerun `agentic eval` after changing the chain.
- The OpenRouter key the user pasted (2026-11-01) is a free-tier key that expires 2026-11-02 with 50 free-model requests/day; a new one is needed after that. Treat both pasted keys as exposed: rotate.
- The user pasted a Groq key in chat on 2026-11-01; it was used only through env vars. They should rotate it at console.groq.com and keep it in `~/.zshrc` as `GROQ_API_KEY`.
- Default provider chain (verified against OpenRouter's public model list on 2026-11-01): `cohere/north-mini-code:free`, `google/gemma-4-31b-it:free`, `nvidia/nemotron-3.5-lightning:free`, `openrouter/free`, then local Ollama. Free IDs change and some are retired (a few listed "going away"), so `agentic models` lists current free tool-calling models. One OpenRouter key serves the whole chain; the free-tier rate limit is account-wide, so per-provider `daily_calls` counters don't add up across entries.
- DNS rebinding is closed: `web.PinnedTransport` resolves a host once, checks every address, and connects to that exact IP (Host header and TLS name stay the hostname). Hard links and odd names are closed too: `secret_reason()` in `safety/protected.py` flags a name match, a hard link (nlink>1, so its data may be outside the workspace) and file contents that are a private key or a known token format; such files are hidden from scans, grep, repo_map, embeddings, commits and the shell sandbox, a direct read of a content-flagged file stays redacted, and a hard-linked file cannot be read or written; `run_shell` refuses `ln` without `-s` (the macOS sandbox already refuses linking a file from outside). Known remaining risks: a secret with an unknown format and an innocent name and no token shape; hard links made by a program rather than `ln` when no sandbox is available. A model can still be tricked into asking for something harmful: the human approval prompt is the last line of defence.
- The sandbox restricts writes and network, and on macOS hides credential directories from reads; other reads outside the workspace are still allowed. Each shell command still asks for approval.
- Protected files (.env, keys) are hidden from shell commands by the OS sandbox (macOS) or Docker mounts; with no sandbox available only the name and glob checks apply, and `$(printf ...)` style obfuscation can still bypass them.
- `sandbox-exec` is macOS-only; elsewhere set `[sandbox] docker_image` (needs docker) or shell commands run unwrapped.
- `web_search` scrapes DuckDuckGo's HTML page unless `[search] searxng_url` is set, which can change layout or rate-limit.
- The orchestrator is keyword-based first; the model is asked only for ambiguous requests, and only from the CLI (the web UI is keyword-only).
- The Anthropic adapter, SearXNG, docker sandbox, model routing and the two offline evals are tested with fake transports/models only; no live run yet (no keys were set in this session).

## Personalizing
Create `~/.config/agentic/profile.md` with a few lines about you (skills, laptop, goals, free-tool preference); every agent reads it each run, and the ideator uses it heavily. Put project conventions in `AGENTS.md` in the repo; the agent's own `remember` notes go to `.agentic/notes.md`.

## Using it with VS Code / Antigravity
No integration is required: run `agentic` in the editor terminal, or open the web UI beside it; edits land on disk and the editor reloads them. For context inside the editor's own AI, add an MCP server with command `/abs/path/.venv/bin/agentic` and args `mcp --workspace /abs/path/to/project` (read-only; check your editor's MCP settings for the exact file).

## How to run
```
uv venv --python 3.12 && uv pip install -e ".[dev]"
.venv/bin/agentic init && .venv/bin/agentic providers
export OPENROUTER_API_KEY=...        # or run Ollama
.venv/bin/agentic serve              # web UI at the printed URL
.venv/bin/agentic run "task" --workspace ./project
```
